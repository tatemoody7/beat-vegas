# Hypothesis registry

One row per idea ever tested or proposed against Beat Vegas data, with its status, the
data it used, its n, how many comparisons were run on that data, the pass criterion that
was written **before** the numbers were read, and the document that holds the result.
`tests/test_hypotheses_registry.py` keeps every study document pointed at from here and
every status word in the vocabulary below.

Why it exists (2026-09-15): nine studies live in nine documents and the count of looks at
the 1,902 real-close games of 2023-25 was written down nowhere. That season set is
**exploratory / in-sample** from here on. Anything important is validated prospectively on
2026+ decisions using locked decision-time state. Add the row first, run the script second.

The "external review" that `TWO_SIDED.md`, `WEATHER_STYLE.md` and the share-engine spec
refer to is the 2026-09-13 write-up filed at
`docs/external/2026-09-13-chatgpt-cfb-totals-review.pdf`; `docs/EXTERNAL_REVIEW.md` maps
its claims to the rows below.

## Program budget (the 2026 ledger, `docs/PROTOCOL_2026.md`, Tate 2026-10-07)

One **5% family-wise Type I budget** covers the 2026 confirmatory program (`H-PROGRAM-2026`),
held as a **fixed ledger of K = 10 tests at 0.5% each**: each confirmatory arm takes one slot when
its own row is registered, and its 0.5% is spent when it ends (promote, stop or timeout) — never
returned. `tests/test_hypotheses_registry.py` reads the list below: the promotion tier must sum to
at most 5%, and each row's criterion must state its share. Slots are added here, one per row, in
the PR that registers the arm; the first three registered 2026-10-08, the two weather arms
(slots 6-7) 2026-10-09, the high-total arm (slot 8) 2026-10-10; 4 of 10 remain, with 4-5
reserved for derivative consistency and stale lines.

## Vocabulary

- **status** — `pre-registered` (criterion written, not yet run), `exploratory` (counts
  and intervals only, no adoption decision may come from it), `tested-null`,
  `tested-positive`, `live-tracking`, `rejected`, `superseded` (closed undecided because a
  later row measures the same question on a changed rule or was never licensed; its
  observations stay as history and never merge into the successor), `adopted`.
- **family** — the error-control family the row's test belongs to. Rows in one family
  share one false-positive budget (Holm across the family, or an alpha split). `exploratory`
  rows carry no confirmatory alpha at all.
- **comparisons run** — how many distinct tests were read on that dataset for that row. For
  rows backfilled after the fact this may be `unknown` or `≥N`, marked `(retrospective)`;
  an invented integer is worse than an honest unknown.
- **n** — the observations the primary test used, with the cut named.

## How to add a row

1. Write the row — question, data, the exact criterion — and commit it.
2. Then write the script. It imports `beatvegas/backtest/harness.py` for the frame, the
   folds, the real closes and the record (`docs/HARNESS.md`), names its `--row <id>`, and
   runs ONCE on the runner via `study.yml`; no unattended iteration. The commit with the
   row precedes the commit with the script.
3. When the result is in, change `status`, fill `n` and `comparisons run`, and point
   `result doc` at the committed document. Never edit the criterion cell after the run;
   if the criterion was wrong, add a new row.

## The model fix (Tate, 2026-10-10)

After the 2003+ switch (H-HIST, 2026-10-07) the champion's number tracked a raw early-season
scoring projection far more than before (week 6 of 2026: correlation 0.76, was 0.26; Georgia @
Alabama 34.8 against Hard Rock's 25.5). Four defects were found read-only on 2026-10-10: every bowl
game (836, 2003-25) is filed as week 1, so `_season_to_date` (sorted by week) let a bowl result
into every later regular-season mean of its own season, a leak; seasons before 2015 lack most of the
richer inputs; sklearn's `early_stopping='auto'` switched on above 10,000 rows with a random
holdout; early averages carry no shrinkage. Tate chose to test the four fixes together and to adopt
them on a pass. The row is written before the script. Result (2026-10-10): NOT MET, so the live
model stays and model work stops (Tate; `docs/MODEL_FIX.md`).
