# Upper bounds are deliberate. Every scheduled job runs `pip install -e .`
# against PyPI at trigger time with DATABASE_URL and both API keys in the
# environment, so an unbounded floor meant a major release of any of these could
# land on a Saturday morning and break the card build with no warning and no
# change on our side. The floors stay where they were; the ceilings stop the
# next major, not the next patch.
#
# The ceilings are raised only on evidence. pytest <9 -> <10 and the lock's
# setuptools <81 -> <85 clear two advisories (a tmpdir handling flaw and a
# MANIFEST.in exclusion bypass) whose only fixed releases need Python >= 3.10.
# That is safe BECAUSE pip honours Requires-Python: the 3.11 runner resolves to
# pytest 9.x / setuptools 84, and this Mac's 3.9 venv keeps resolving to pytest
# 8.4.2 from the same range. Measured 2026-09-20: the full suite passes under
# pytest 9.1.1 + setuptools 84 (1,161 passed, 15 skipped).
#
# NOT a substitute for a hash-pinned lockfile, which is what actually defends
# against a compromised release rather than merely a breaking one. That needs a
# 3.11 toolchain to resolve against (the workflows' runtime) and is tracked
# separately -- see the review notes.
#
# matplotlib is NOT here: only scripts/fetch_team_logos.py (an August, laptop-only
# job) imports it, and on the runner it dragged in contourpy/pillow/fonttools and a
# contourpy release that needs Python 3.12. It is the `logos` extra in
# pyproject.toml: `pip install -e ".[logos]"`.
