# Upper bounds are deliberate. Every scheduled job runs `pip install -e .`
# against PyPI at trigger time with DATABASE_URL and both API keys in the
# environment, so an unbounded floor meant a major release of any of these could
# land on a Saturday morning and break the card build with no warning and no
# change on our side. The floors stay where they were; the ceilings stop the
# next major, not the next patch.
#
# NOT a substitute for a hash-pinned lockfile, which is what actually defends
# against a compromised release rather than merely a breaking one. That needs a
# 3.11 toolchain to resolve against (the workflows' runtime) and is tracked
# separately -- see the review notes.
